# 平台生命周期路线图

当前产品边界见[决策 0001](decisions/0001-platform-first.md)。路线图区分正在交付的基础和后续能力，不能把计划项写成可执行安装命令。

## 第一阶段：独立平台与统一入口

本阶段 v0.2.0 收敛四个边界：

1. 独立平台入口提供 Web、HTTP API、学习业务与持久化。
2. CLI 管理本地启动、连接诊断和命名端点；学习操作全部通过 HTTP。
3. GitHub 学习包由平台获取、校验和保存；Web 可安装 GitHub 包、上传纯数据包、查看版本。
4. Skill 只保留 CLI 使用说明和教学流程，MCP 退出默认产品与依赖。

保留已验证的课程快照、评分、幂等、学习证据、复习和迁移语义。实际完成情况以[当前验收](verification.md)为准。

## 第二阶段：多媒体课程与平台资源管理

每轮 Agent 教学可使用文字、图片、音频和视频。这是核心课程能力，优先于下载安装器推进；当前仍为待实现设计，见[多媒体课程与资源](architecture.md#多媒体课程与资源待实现)。

1. 课程引入有序内容块，兼容既有文本课程，支持图文、音视频与练习编排。
2. 平台接收并保存 Agent 上传和学习包携带的媒体；数据库保存元数据与稳定引用，本地文件与云端对象存储由平台适配，CLI 提供 HTTP 上传入口。
3. 发布校验资源就绪并固定内容版本；Web 提供播放、说明和字幕，资源权限与课程、题目及评价依据的可见性一致。
4. 导出、恢复和迁移涵盖媒体文件与完整性校验，历史课不受包升级或临时文件清理影响。

分步验收图片、音视频、学习包资源和含媒体的恢复，不能只完成播放器就宣称多媒体课程交付。当前有界聚合及容量错误继续有效，扩容需显式存储版本迁移。

## 第三阶段：可分发的应用版本

先确定项目与内容许可证，再建立发布版本、变更记录和稳定的版本元信息。产物应明确包含平台运行文件、Web 静态资源、schema 迁移和校验信息，标明支持的系统与 Node 要求。

安装器或 CLI 安装入口负责获取并验证产物、选择实例目录、初始化配置。平台拥有自己的版本与数据目录，不能把某个开发源码工作区当作用户应用安装目录。当前仍从源码构建，没有已发布 npm 包、下载版安装器或一键部署服务。

## 第四阶段：可靠更新

建立升级检查、兼容性判断、升级前备份、数据库迁移、健康检查、失败恢复与回滚。学习数据与安装文件分开，更新失败不能留下半套 schema 或覆盖历史题目与成绩。

学习包版本单独管理：平台可检查来源并下载新版本，已有目标采用哪个版本有明确规则。包更新不隐式修改旧课程和用户证据。

## 第五阶段：可选择的自动升级

可靠的手动更新路径稳定后，再支持用户选择启用自动检查和升级策略。平台/发布系统负责一致性与恢复，CLI 和 Web 提供配置及操作入口。当前没有常驻更新器、守护进程监管、自动云资源创建或自动提醒。

## 独立后续工作

当前 1,500,000 字节有界聚合的扩容、可选轻量学习包格式，以及其他宿主适配分别立项。多媒体资源已列入第二阶段核心能力。当前阶段不加入市场、付费、团队、多租户或双向同步。
